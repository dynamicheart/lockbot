# LockBot

{{LOCKBOT_CONNECTION}}

## Make sure lb is available

Run `command -v lb` and `lb version`. If the installed LockBot CLI works, use it as-is.

If `lb` is missing and the user has asked you to use LockBot, install it in their current environment:

{{LOCKBOT_LB_INSTALL_SOURCE}}

1. Run `uname -s` and `uname -m`. Select `darwin` for macOS or `linux` for Linux, and `arm64` for `arm64` or `aarch64`, or `amd64` for `x86_64`. Use the combined platform key, such as `linux-arm64`.
2. Fetch the JSON release manifest over approved internal network access. In `artifacts[platform]`, read `url` and `sha256`. Download that HTTPS binary from the same release origin to a temporary file. Use no LockBot Key for either download.
3. Verify the binary's SHA-256 against the manifest before executing it. Install it as executable `~/.local/bin/lb`, then verify with `~/.local/bin/lb version`. Use that full path if the directory is outside PATH. Stop if the platform is unsupported, a download fails, the digest differs, or the installed binary fails to run.

## Connect to LockBot

Use the user's selected LockBot server. Check `lb connections` for locally saved servers and `lb bots --details` for authorized bots. Only use a server address the user has approved. If access is missing, ask before starting a binding. `lb login <server>` and `lb bind` can issue binding codes. A request to install or update the Skill, use a server, or look up resources does not authorize either command. After explicit authorization, send the code to the user for confirmation in the target chat, then repeat the same command. Keep personal Keys and binding proofs private.

## Verify the target before writing

- For a named target, inspect all matching resources in the applicable connections. If more than one target matches, ask the user to choose the bot or card before writing. Use the selected exact `resource_ref`. A request to choose any suitable resource allows you to select a verified match.
- For a model requirement, verify the model using reported hardware for the requested node or cards. A label, node name, or bot name is not hardware evidence. If the requested model or whole-node coverage cannot be verified, stop and ask before locking or booking. A card lock is not a substitute for a requested whole-node lock.

- Before a mutation, check freshness with `lb resource view <node> --json`. If a query reports an incomplete or stale snapshot (for example, `complete: false`), query again. Proceed only after a fresh, complete result confirms the target. If it still cannot be verified, report that and stop without writing. A REF copied from a stale or incomplete response does not establish a valid target.

## Use lb

- Find resources with `lb resource list --model P800 --available card`. Inspect a node with `lb resource view <node> --json` and check its bot, card, and hardware. Select a card with `--card <number>`.
- Use the resource's supported operations. `lb lock <node> 30m` is for a whole node. Add `--card <number>` for a card node, and use `--shared` only where supported. When asked to lock multiple cards together on one node, send one command with repeated flags, for example `lb lock <node> 2h --card 2 --card 3`. `lb book <node> 30m` joins a queue where available. When your booking is ready, use `lb lock <booking_ref>` to start using the reserved resource. Use `lb free` to release your lock or cancel a booking.
- Watch changes with `lb resource watch <node>` or `lb resource watch --mine`. Use `--json` for machine-readable events and Ctrl+C to stop. Prefer the event stream for ongoing monitoring.
- Read utilization with `lb resource metrics <node>` or choose a particular card using `--card <number>`. A resource marked `ready` has a configured metrics source. Bot authorization is enough to read supported metrics.

Check the result of every resource mutation with a fresh query before reporting success. After a write returns HTTP 504, `gateway_timeout`, or `may_have_executed`, query the exact affected resources to verify the requested result. If it is visible, report it. If it cannot be confirmed, report the result as unknown and stop. An unchanged or incomplete read does not prove the write failed. Never submit the write again based on that read. The service's HTTP API reference is at `/api/public-docs/agent-v2`.
