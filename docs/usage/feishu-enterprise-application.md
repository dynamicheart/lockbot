# 正式企业 Lockbot 应用申请草案

**供维护者先审核，不是已提交的申请。** 目标是昆仑芯企业内的一个自建 Lockbot 应用，供经批准的同事添加到资源群；一个企业应用服务多个群，每群在 Lockbot 中显式关联一个独立资源机器人。如流继续保留，不共享两个平台的资源池、身份或个人 key。本材料不代表已进入正式企业后台、创建应用、开通权限、扩大范围、提交或发布；测试企业的授权不能用于推定正式企业授权。

## 申请理由与建议基线

用于群内资源查询、申请、排队、到期提醒、Agent 绑定和只读资源网页。接收群内真实 @ 的命令并回复，不读取全部聊天、不处理单聊；姓名/群名帮助同事及管理员辨认使用者和资源群，鉴权仍使用稳定的平台 ID。

| 审核项 | 建议申请内容 | 边界 |
| --- | --- | --- |
| 应用能力 | 企业自建应用，启用机器人能力 | 不是自定义群 Webhook；一个应用可加入多个经批准资源群 |
| 应用身份 API 权限 | `im:message.group_at_msg:readonly` | 接收群内真实 @机器人消息；订阅 `im.message.receive_v1` |
| 应用身份 API 权限 | `im:message:send_as_bot` | 发送查询、操作反馈、排队/到期提醒和授权的群通知 |
| 应用身份 API 权限 | `im:chat:read` | 查询已关联群的名称等基本信息，避免后台只显示 Chat ID |
| 姓名解析 API 调用权限 | `contact:contact.base:readonly` | 允许调用当前使用的用户信息查询 API；不等于批准全企业通讯录范围 |
| 姓名解析字段权限 | `contact:user.base:readonly` | 允许返回姓名等基本字段，与上项调用权限互补，不能因名称相似删掉其一；不申请手机号/邮箱 |
| 应用可用范围 | **建议企业全员可用，供维护者审批；尚未设置或获批** | 使企业内获准同事能发现并按群规则添加 Lockbot，即使应用负责人不在该群。它不扩大通讯录数据范围、API 权限或 Lockbot 资源权限；审批结果与实际发布仍须记录 |
| 通讯录数据范围 | **仅与已批准使用人员相匹配的最小范围，具体控制台选项待现场核对** | 用于把参与者 Open ID 解析为姓名；应用可用范围与数据范围分别审核，不要求浏览全企业通讯录或遍历群成员 |

基线共五项 API 权限。缺少姓名查询时核心资源命令可回退稳定 ID，但本次目标是可管理的姓名化后台，建议保留两项互补联系人权限。企业当前“免审/需审”标记、字段可见性和数据范围必须现场核对；“免审权限”不代表免应用版本发布、免企业批准或免成员范围审核。完整说明见[飞书接入](feishu.md#权限与审核)；[官方用户信息接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/contact-v3/user/get)是调用/字段权限的核对来源。

## 同事能拉进群，还需要分别满足什么

1. **企业应用发布与可用范围**：按企业审批规则发布，目标同事必须在已批准范围内。操作入口以实际控制台为准；现有[图文指南](feishu-setup.md)中的“权限管理 / 事件与回调 / 版本管理与发布”来自真实测试后台，不保证正式企业界面相同。
2. **群内添加资格**：是否允许普通成员添加机器人、是否仅群主/群管理员可添加、是否限制应用类型/外部群，是群设置及企业策略问题。**正式企业当前策略未核实，需群管理员/IT现场确认**；应用可用不等于任意群均可添加。不要通过扩大通讯录或消息权限绕过限制。
3. **Lockbot 显式资源绑定**：入群不自动暴露资源或创建授权。用已发布版本支持的群内真实 @ 引导取得 Chat ID，由超级管理员在 Lockbot 关联正确企业应用、精确群和资源 bot，再交给对应管理员管理。未绑定群保持引导/不执行资源命令；一个群只关联一个资源 bot。资源成员、平台用户、个人 key 和其它群保持隔离。

## 应用负责人不在群时，由获准同事添加

目标不是要求应用负责人或 Lockbot 站点维护者加入每个资源群。**同一企业内的获准同事可以在自己有添加资格的群中添加已发布的 Lockbot**；添加者须在已批准的应用可用范围内，同时满足该群及企业的机器人管理规则。为方便企业同事发现应用，上表建议“企业全员可用”，但这只是待审核草案，不能据此自动修改控制台。

飞书官方[在群组中使用机器人](https://www.feishu.cn/hc/zh-CN/articles/360024984973-在群组中使用机器人)说明应用可用范围与群管理设置影响添加资格；[配置飞书群的官方示例](https://www.feishu.cn/content/389799179937)也说明开发者不在目标群时，可先由群内人员添加机器人。后者是飞书连接器场景参考，不代表 Lockbot 使用其连接器或继承其权限。实际添加是否成功仍须按本企业规则验收。

分别核对以下边界：

- **应用可用范围**决定谁可发现、使用或添加应用；**通讯录数据范围**仍只按姓名解析需求单独审核，不因全员可用而自动变为全企业读取。
- **群主/群管理员设置**独立生效；若仅管理员可添加，由有资格者操作，不能靠增加 API 权限绕过。无需申请写入群成员或读取全部消息来实现人工添加。
- 此处仅指**同一企业的内部群**，不申请跨企业外部群共享或应用对外分发。
- 入群后仍须超级管理员显式关联精确群与资源 bot；同事添加应用不自动取得本站管理权、个人 Agent key 或其它群资源。

### 待执行的实际验收用例

- [ ] 选择同一企业内、已明确授权的资源测试群，确认应用负责人/本次需求提出者**不在目标群**；通过私有记录核验，不公开成员列表或群标识。
- [ ] 由应用可用范围内且符合群管理规则的同事，从群设置搜索并添加已发布的 Lockbot；如被群策略拒绝，记录原因并交群管理员处理，不扩大 API 或通讯录权限。
- [ ] 未绑定时真实 @机器人只返回本站配置引导，不执行资源命令或自动绑定；由超级管理员通过私有渠道完成明确的群/资源关联。
- [ ] 在已授权的虚构资源上验证真实 @查询与群间隔离；消息/资源修改另按具体授权执行，不能以本草案代替发送批准。
- [ ] 记录添加者资格、应用范围、群规则、发布版本与实际结果；测试结束按明确约定清理。**本用例尚未执行，不以已有双群测试或官方示例冒称完成。**

## 可选增强单独审核，本次不并入基线

| 可选项 | 另需内容 | 默认与处理 |
| --- | --- | --- |
| 进群引导/退群观察 | `im:chat.members:bot_access`；订阅 [`im.chat.member.bot.added_v1`](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat-member-bot/events/added) / [`im.chat.member.bot.deleted_v1`](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat-member-bot/events/deleted) | 本站相关开关默认关闭；不是群成员列表读取权限。不影响基线真实 @ 后的未绑定群引导 |
| 成功操作表情回复 | [`im:message.reactions:write_only`](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message-reaction/create) | `FEISHU_REACTION_REPLIES` 默认关闭；需单独确认权限及版本发布，失败回退文字，不重放操作 |
| 原地更新查询面板 | 当前[编辑消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/update)与本实现沿用基线发送权限，编辑本应用自己发送的消息 | `FEISHU_QUERY_PANEL` 默认关闭；不为面板申请全部消息读取，实际企业编辑能力/时限仍需授权群验收 |

**不申请** `im:message.p2p_msg:readonly`、全部群消息/历史读取、群成员列表、手机号、邮箱或全企业通讯录遍历。测试企业可选功能的批准、真实面板样例或软件候选合入都不构成正式企业的申请授权；先按所部署版本和本次获批功能核对。

## 提交前确认与验收清单

- [ ] 维护者确认正式企业、应用名称/负责人、目标同事及资源群，并明确审批是否采用建议的“企业全员可用”（与通讯录数据范围分开）；明确只申请上表五项基线，还是另行批准指定增强项。不要在公开 Issue 填成员清单、群 ID、App ID、Secret 或内部地址。
- [ ] 现场分别核对能力、权限审批标记、应用可用范围、通讯录数据范围和群添加策略；按[官方企业应用审核说明](https://open.feishu.cn/document/home/intro-to-custom-app-review)及本企业规则由授权人员完成申请/审批/发布。本文未核实正式企业的这些结果。
- [ ] 超级管理员通过私有配置渠道录入凭证；长连接只需出站 HTTPS/WebSocket，代理/网络由 IT 批准，无需公网入站和单聊权限。同应用仅一个受管接收端，不同时保留测试接收器争抢事件。
- [ ] 在明确授权的两个群配置不同虚构资源，确认应用可发现/可添加、真实 @ 查询、姓名/群名或 ID 回退、短锁/排队/提醒/释放、Agent 绑定和本站网页链接；验证资源、用户和消息不串群。需要发送测试消息或改状态时再取得具体授权。
- [ ] 普通 bot 管理员/OP/其它 Agent 看不到他人的 Agent 详细任务备注；只有本人、显式超级管理员读取或单独授予的详细备注审计能力可按各自权限读取。测试结束核对租约归属再清理，不重试结果不明的修改请求。

审核这份草案只确定拟申请范围，不等于批准外部控制台操作、正式服务升级或启用增强开关。后续记录批准人/范围、应用发布结果、部署版本和实际验收，分清代码、企业授权与上线三条证据。
