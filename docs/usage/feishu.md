# 飞书接入

首次配置可按[图文接入指南](feishu-setup.md)操作。

一个企业自建应用可以服务多个资源群。每个群对应一个独立的 Lockbot 资源机器人，分别管理资源、规则、用途和个人授权。无需为每个资源群创建一套企业应用。

## 部署与最小权限

Docker 镜像包含飞书长连接依赖。Python 部署安装 `pip install 'lockbot[feishu]'`。长连接由服务主动访问飞书 HTTPS／WebSocket，无需公网入站地址、临时隧道、Verification Token 或 Encrypt Key。

在飞书开发者后台创建企业自建应用，添加机器人能力，订阅 `im.message.receive_v1`。仅支持群内真实 @；不要求单聊消息权限。

### 权限与审核

以下为 2026-10-29 在测试企业开发者控制台、应用身份（`tenant_access_token`）下逐项核对的标记。正式接入时仍应核对当前控制台；不要把测试企业结果当成所有企业的免审批承诺。

| 权限 | 用途 | 是否必需 | 本次控制台标记 |
| --- | --- | --- | --- |
| `im:message.group_at_msg:readonly` | 接收群内 @机器人的消息 | 必需 | 免审权限 |
| `im:message:send_as_bot` | 发送群回复和提醒 | 必需 | 免审权限 |
| `im:chat:read` | 查询指定群名称等基本信息 | 推荐，缺少时只显示 Chat ID | 免审权限 |
| `contact:user.base:readonly` | 姓名等基本信息的字段权限 | 姓名化后台所需，与下项API调用权限互补；核心资源命令可在缺少时回退ID | 本次观察为免审 |
| `contact:contact.base:readonly` | 调用获取用户信息API的权限 | 姓名化后台所需，与上项字段权限互补；不因名称相似认定冗余 | 本次观察为免审 |
| `im:message.p2p_msg:readonly` | 接收用户单聊消息 | 不支持，不列入部署要求；本次已在控制台关闭并发布生效 | 历史观察为免审，但本项目不使用 |

本轮最小功能没有必须申请的“需审核权限”。读取所有群消息、历史消息、群成员列表、手机号、邮箱或全企业通讯录都不是接入条件，不应为方便调试扩大申请。若另加权限，以控制台实际审核标记为准。

“权限免审”只描述这项 API 权限，不代表应用版本发布、成员可用范围、通讯录数据范围或企业网络访问无需企业管理流程。姓名只是显示信息；身份、配额、锁和授权始终使用平台范围内的稳定 ID。没有姓名权限或缓存时，纯文本、网页和 API 安全回退 Open ID，不影响鉴权、锁定、排队或 Agent 绑定。原生 @ 仍以稳定 Open ID 构造，由飞书客户端解析显示平台名称，不依赖本服务的联系人姓名查询。不能承诺服务端姓名查询始终成功或所有返回都包含姓名。

核心群命令可在没有联系人查询时使用稳定ID；用户需要完整的姓名化后台时，保留上述两项联系人权限组合。[官方获取用户信息接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/contact-v3/user/get)区分 API 调用权限 `contact:contact.base:readonly` 和 name 等字段权限 `contact:user.base:readonly`，两者互补，不是宽窄互换或可删除其一的关系。查询仍受应用可用范围/数据范围约束，不因此读取手机号、邮箱或申请群成员列表。`im:message.p2p_msg:readonly` 独立于姓名解析，本次已关闭且控制台确认当前修改均已发布。控制台“免审”与 Lockbot“功能所需”是两个独立维度：免审不代表应开通；姓名增强权限也不能被误当作资源命令鉴权依据。

应用还需要设置可用成员范围，并完成企业的发布／审核流程。权限已开通、应用已发布、用户在可用范围、机器人已加入资源群，分别是独立的条件。范围只覆盖所有者和少量测试成员时，企业可能允许免审核发布；正式企业以自己的审批策略为准。

如流的群机器人凭证与飞书的企业应用凭证不同。如流原有配置和回调继续使用，已有机器人不会自动转换平台。

站点设置中的「开放的平台」控制新建机器人允许选择如流或飞书；默认都开放，关闭不会自动停用已有机器人或修改个人授权。飞书企业应用凭证仍由超级管理员在同一页面集中配置。

## 配置顺序

1. 超级管理员进入 Lockbot「站点设置 → 消息平台 → 飞书应用」，添加应用名称、App ID 和 App Secret，选择「长连接」。服务器向飞书核对应用自己的机器人身份。秘密加密存储，列表不返回明文。
2. 创建资源机器人，平台选择「飞书 / Feishu」，选择该企业应用，填写资源群的 `oc_...` Chat ID 并配置资源。不知道 Chat ID 时，先将应用机器人加入资源群，再真实 @机器人取得当前群标识和配置/绑定指引；表单标签旁的问号提供相同步骤。群路由需要超级管理员明确授权；随后可以把资源机器人转移给对应管理员管理。一个应用的一个群只能对应一个资源机器人。
3. 在飞书应用列表启动连接任务。在飞书开发者后台的「事件与回调」选择长连接，验证显示连接成功后保存，并发布应用配置。这里的应用版本号与 Lockbot 软件版本号相互独立。
4. 将机器人加入已授权群，发送 `@机器人 help` 或直接 @机器人。只有真实提及当前机器人的群内文字消息会执行业务。首版不处理单聊资源操作和非文字命令。
5. Agent 读取本服务的 Skill，申请绑定码，用户在对应资源群发送 `@机器人 bind <绑定码>`。绑定成功后，Agent 用自己的个人 key 查询 `/api/agent/context`，取得 bot、规则和 API 链接。不能复用另一个平台或另一个机器人的 key。

长连接首次接收到已授权群的可信事件时，会记录并固定企业租户范围。HTTP 事件不能建立或更改这个范围。应用只向已配置群回复；机器人被拉进新群，不会自动开放该群的资源权限。

## 命令与消息

资源命令与如流一致，具体以当前机器人 `help` 和 Agent API 的 `command_examples` 为准。`book` 只是排队；收到可用提醒后仍需 `lock`，并查询状态确认自己已经持有资源。

回复使用飞书原生富文本：emoji 保留，超链接使用链接节点，真实提及使用用户 Open ID。普通备注里的 HTML／Markdown 或 `<at ...>` 字样不会被解析成真实提及。Agent 操作提示沿用机器人已有开关，不给每条 API 操作增加 @。姓名只用于展示，权限、排队、用途和个人 key 使用稳定身份。

## 接收、重启与回退

每个应用共用一个受管理的 SDK 子进程；同一应用的资源群不会各自建立连接。停止服务时回收连接器，重连使用有限退避。如流不依赖飞书连接成功。

消息进入有界执行队列前，先保存应用范围内的消息 ID 去重记录。重复投递不会重复续期。记录不保存聊天正文或绑定码；资源操作和用途继续使用原有日志与存储。超过接收时效的消息和等待过久的任务不会延后执行。进程在执行期间崩溃时，结果可能不确定，不能自动重放修改命令，应先检查资源状态。

升级只新增飞书相关数据库表。旧如流数据保持原样。备份归档包含应用和群路由；选择性恢复按 App ID、租户及机器人身份匹配应用，不使用来源数据库的数字 ID。目标上已经轮换的应用凭证会保留；跨租户冲突、无法解密和群路由冲突会拒绝恢复。

回退到不支持飞书的旧版本前，先停止飞书接收和相关资源机器人，保留数据备份。如流可以继续运行；旧版本不能接管飞书机器人。正式服务升级和软件发版仍需要独立验收。

HTTP 回调是可选入口：需要稳定 HTTPS URL、明确的租户范围和 Verification Token；配置 Encrypt Key 后只接受加密事件并校验原始请求签名。同一应用只启用一种接收方式，不能同时启动多个开发环境争抢长连接事件。

参考：[飞书长连接接收事件](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/server-side-sdk/python--sdk/handle-events)、[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[消息结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json)。

后台通过已关联应用查询指定群的名称，群名仅用于展示，鉴权和路由仍使用 Chat ID。群名缓存在服务进程内，成功保留 6 小时，失败退避 5 分钟；管理员可手动刷新。失去权限或临时失败时保留最近已知名称并显示状态，不影响已有资源锁和个人授权。创建表单的群名预览仅超级管理员可用；详情页只允许现有 bot 的授权管理者查询已关联群。


## 平台边界与迁移

如流凭证继续保存在原 bot 字段；飞书 App ID、加密的 App Secret 和接收设置保存在 `feishu_applications`，`feishu_group_routes` 明确关联应用、群与资源 bot。个人授权保留平台身份范围；后台管理员账号与群聊用户身份不是同一种账号。不按姓名自动合并如流账号和飞书 Open ID，也不把另一平台的个人 key 直接转用。

一个 bot 在创建时固定平台。迁移使用详情页的“复制配置”，打开新建页面后选择目标平台与群。只复制资源定义、规则、显示设置和 Agent 开关；不复制群关联、应用凭证、个人授权、OP key、用户例外名单、实时锁、队列或历史日志。新旧 bot 状态独立，管理同一批真实资源时应先停用旧入口，不能同时发放两套独立的锁。不支持一个资源机器人跨平台共享资源池。

命令执行和资源状态共用现有核心逻辑；平台 Adapter 分别构造原生链接、提及和消息发送。当前业务层仍有格式化文本，这不是已经完全平台中立的语义消息模型。群消息、API 通知、提醒和预览需要分别做两平台回归，不能只验证一条 echo。

## 网络与代理边界

长连接需要出站访问飞书 HTTPS 和 WebSocket，并不等于无须遵守企业网络策略。企业代理或出口可能记录目的域名、连接时长和流量；若有 TLS 检查，可见范围取决于企业配置。本项目不能代替企业判断是否允许，不关闭 TLS 校验，也不提供规避监控的方法。

部署可以设置 `LOCKBOT_FEISHU_PROXY_URL=http://proxy.example.com:8188`，显式覆盖飞书 HTTP API、SDK 获取连接地址的 HTTP 请求及 WebSocket。此设置不修改全局 `HTTP_PROXY` / `HTTPS_PROXY`，不改变如流请求。默认跟随此部署级飞书专用设置，所有飞书应用共用。超级管理员可在站点设置覆盖为直连或指定代理，保存后受控重连；直接修改部署环境变量仍需重启服务。尚未提供逐应用独立代理配置。

只支持不带用户名、密码、查询参数或路径的 HTTP(S) 代理地址。不把代理认证信息写进环境变量或日志。代理模式依赖固定版本的 `websockets==15.0.1`；若所安装版本没有显式代理参数，连接器拒绝启动，不静默改为直连。代理失败仍使用原有有界退避重连，不自动重放结果不明的消息发送。

验收应分别检查 token/机器人身份请求、WebSocket 的代理路径、群内真实 @ 后的接收与回复，以及断线重连。HTTP 请求成功、代理 TCP 连接存在或 SDK 进程存活，都不能单独证明已通过真实群消息端到端验证。不在生产日志中输出带连接票据的 WebSocket URL。

WebSocket 代理参数参考 [websockets 15.0.1 代理文档](https://websockets.readthedocs.io/en/15.0.1/topics/proxies.html)。SDK 适配只安装在飞书专用子进程中；更新 SDK 时应重新运行连接器和代理测试。

## 当前集成版本与测试工具

PR #25 当前源码已合并严格任务权限、历史/公开 OP 历史和通知尾部队列的主线实现，仍是未发布的飞书候选。普通 bot 管理员与 OP 维护凭证不能读取其他用户的私密用途/Agent 名称；姓名和容器展示信息不改变这项权限。同一用户共用个人 key 的多个 Agent 也不是彼此隔离的私密身份。正式服务目前为 v2.15.2，不包含本候选。

PR #23 的消息 gallery 是独立开发诊断，不是生产连接器，也不是本功能的安装依赖。当前消息格式首先由生产 Adapter 的隔离测试验证；若使用 gallery，先确认其版本和明确授权的目标/实际内容，默认只做 dry-run，不能借此启动第二个真实接收端。

群路由创建需要超级管理员明确授权。Chat ID 格式校验或成功查到群名都不能替代人工确认机器人已加入该资源群、用户在应用可用范围内，以及当前企业允许该权限/发布方式。缺少可选查名权限时可继续以稳定 ID 使用核心资源功能；不要为查名补开群历史、成员列表或全企业通讯录权限。文档表中的“免审”是本次测试企业的观察，不保证其他企业、未来控制台或新增权限相同；以部署时企业控制台和管理员审批为准。


### 站点飞书专用代理

超级管理员可在站点设置选择“跟随部署配置”（默认）、“直连”或“指定代理”。默认继续读取 `LOCKBOT_FEISHU_PROXY_URL`，不覆盖现有部署。指定代理仅接受无内嵌用户名/密码、无路径/查询参数的 HTTP(S) 地址。直连会显式关闭飞书 HTTP 与 WebSocket 的环境代理发现；切回跟随部署配置恢复原环境行为。配置保存在站点数据库，重启时在机器人/连接器启动前恢复；公开设置和普通管理员接口不返回代理地址。

保存后后续飞书 HTTP 请求使用同一有效配置；只有传输策略实际改变才清理名称缓存，停止旧应用接收端后再启动新接收端。断连不重放资源命令。保存成功不等于 WebSocket 已握手；界面分别报告连接待就绪/需重启。“测试已保存的 HTTP 连接”仅调用固定官方机器人身份 API，不访问用户指定测试 URL，也不能代替真实 WebSocket/群事件验收。不设置全局 `HTTP_PROXY`，不改变如流或指标数据源。当前进程内保证一个应用一个接收端；多实例部署仍需运维统一选择接收端。

新建表单的消息平台切换只更新平台相关字段：清空旧群/应用选择与另一平台凭据，清除对应校验提示，不因规则变化立即把整表标红。必填校验仍在用户交互或提交时执行。已创建机器人的平台仍不可直接切换，迁移继续使用复制配置流程。
