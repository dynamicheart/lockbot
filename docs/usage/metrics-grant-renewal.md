# 持续查看利用率与短期授权续领

资源网页链接和利用率授权是两种独立凭据：链接可由平台／机器人配置为 30 天或永久；数据源的 `metrics:read` 授权仍最多 300 秒。延长网页链接不会延长指标 token，也不意味着允许匿名访问数据源。

浏览器仅在内存中保存短期 token。每轮查询前检查有效期；不足 30 秒时，经当前 Lockbot 服务、当前机器人和当前网页授权换取新 token，再直接查询数据源。后台页面使用已登录账号的授权接口；只读页使用同源的状态接口，并检查返回的数据源配置与本次查询一致。个人 key、OP key、管理 JWT 和网页只读码均不会转发给数据源。独立数据源凭据模式保持原有行为。

数据源返回 401／403 时，最多强制续领一次、重试查询一次。429 及 `Retry-After` 必须等待，不能靠换 token 绕过；其它失败采用已有退避。授权、首次查询和这一次重试共享 15 秒总预算，保持原有查询批次和最短轮询间隔，不触发硬件重新采集。

每轮固定绝对截止时间，在授权响应、指标查询、强制续领和最终发布前复核。系统睡眠后即使超时定时器尚未执行，也会丢弃过期轮次，不继续续领或重试。唤醒后才收到的 `Retry-After` 从接收时开始等待，不减去此前睡眠时间。

隐藏页面不查询，恢复后检查当前授权；系统睡眠期间即使浏览器单调时钟暂停，也按已实际经过的时间恢复调度。尚未经过的轮询下限和限流等待仍保留。切换机器人、数据源、网页码或丢失权限时取消旧请求并丢弃迟到结果。

重新生成只读链接后，旧码不能再续领授权。已经签发的指标授权仍受原始到期时间和网关验签时钟容差约束；需要立即停止访问时，应在独立指标网关撤销／禁用对应授权范围。不能把网页码轮换误认为已签发 token 的即时撤销。

Agent 同样应在使用前检查 `expires_at`，临期时按正常 API 预算重新读取当前服务的 `/api/agent/context`，只将返回的 `utilization.access.token` 用于其指定的 `utilization.configuration.endpoint`。这不是一个可永久保存或跨服务复用的 key。长时间打开网页不需要用户手动更新链接；数据源不可达、授权撤销或样本过期仍应明确显示不可用，不能将旧数据视为空闲。

部署后应在 8002 完成跨一次真实五分钟到期的验收：保持同一资源链接连续查看、隐藏后恢复，并确认没有手动替换 token／链接；再检查旧码轮换与限流。单元测试不替代这项浏览器和真实服务验收。
