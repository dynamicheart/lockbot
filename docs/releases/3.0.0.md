# 3.0.0 release checklist

The release adds Feishu alongside Infoflow. It keeps published Agent API routes and existing Infoflow configuration and keys. One Feishu enterprise application serves explicitly authorized resource groups, with a separate resource bot per group. Direct messages and shared cross-platform resource pools are unsupported.

## Production application approval gate

Use the production enterprise application for the formal deployment. Keep the test-enterprise application and credentials restricted to integration testing. Prepare the application identity, minimum permission set, event subscription, proxy and group-routing plan for the maintainer's review **before submitting an approval request or publishing application configuration**. A successful test-enterprise integration does not authorize production permission changes. Code rollout and enterprise-application approval are separate steps.

## Acceptance gates

- Merge the reviewed Feishu integration and its privacy and monitoring follow-ups into `release/2.x`, with all required checks passing on their current heads.
- Verify group routing, resource commands, links, mentions, proxy recovery and public/private projections on the integration service. Default management reads must remain public; private reads require explicit selection and current super-administrator authority.
- Verify an existing database and state directory upgrade without regenerating keys or losing locks and queues. Feishu adds application, route and message-deduplication tables; it does not convert Infoflow credentials to a different schema.
- Preserve the previous `main` in an archive branch. After acceptance, align `main` to the exact accepted `release/2.x` commit and copy the required-check protection before changing the default branch. Do not rename `release/2.x` or merge obsolete platform implementations from the previous `main`.
- Tag the accepted commit as `v3.0.0`, verify the image and offline artifacts, and record their checksums before upgrading the formal service. Preserve its port, data volume and encryption/JWT configuration.
- Check the formal service after upgrade and update the roadmap and issues using actual results. A test deployment or green CI is not formal deployment evidence.

Database readability does not guarantee a lossless downgrade: older code cannot serve Feishu and may restore older privacy behavior. Preserve a consistent database/state backup and the original encryption key; do not run two receivers or writers against the same state.
