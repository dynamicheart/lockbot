# 3.3.0 release candidate

Status: prepared for review. Publication and formal deployment are pending.

## Changes

- Optional personal resource dashboard with browser confirmation, scoped sessions and private report adapters (PR #124).
- Per-bot credential discovery and recovery within a verified service and platform identity namespace, with nullable encrypted copies for existing keys (PR #128).
- Monitoring bar alignment and credential caller labels (PR #126).
- Skill source URL rendering from the explicit deployment PLATFORM_URL, consistent across Markdown, ZIPs, hashes and version headers (PR #133).
- Separate login identity and report-source groups on the connections page (PR #134).

## Compatibility and rollout

API version remains 1. Keep the original data volume, instance identity, encryption/JWT keys, bot identities and existing personal keys. Startup adds a nullable credential_encrypted column. Existing clients and digest-only keys continue to authenticate. Historical keys become recoverable as their existing holders present them to the recovery endpoint. See [credential recovery](../agent-api/credential-recovery.md).

A live personal key grants discovery/recovery of the same verified principal's other stored keys within the service/platform namespace. Keep this authority explicit when assigning Agents. Feishu recovery requires matching application and tenant evidence. Missing namespace evidence remains bot-scoped.

The dashboard requires an operator-supplied LOCKBOT_PERSONAL_PANEL_CONFIG file. Use the native provider for the formal service. External organization-specific adapters remain privately maintained. Existing 8002 configuration and its browser sessions stay on their independent deployment.

PLATFORM_URL must contain the actual service origin, including scheme and published port. Formal rollout uses the existing 8155 origin.
