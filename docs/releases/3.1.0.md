# Lockbot 3.1.0

## Changes

- Add dedicated, revocable `task_notes:read` audit credentials issued only by a current super administrator. Ordinary OP, personal and management tokens cannot substitute for this credential on the new audit routes.
- Read bounded Agent operation notes or verified live declarations for explicitly authorized bot identities. Search and pagination use a narrow projection; disclosure evidence commits before notes are returned.
- Use wide utilization cells for host metrics and the ordered device list, with a stacked narrow-screen fallback. Bot details remain full width.

## Compatibility

The audit API is additive (version 1). An additive `audit_credentials` table stores token digests and scoped delegation metadata; existing credentials, bot settings and resource state retain their formats and permissions. No credentials are automatically issued. Existing Infoflow/Feishu messages and resource operations are unchanged. This is not the complete lifecycle audit in issue #54.

Feishu reaction replies (#68), in-place queue panels (#62) and membership onboarding (#63) are not part of this release. Corporate application approval and permission publication remain separate human decisions.
