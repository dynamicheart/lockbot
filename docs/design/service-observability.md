# 服务监控与 Agent 操作历史

后台的“服务监控”回答平台现在有多忙、哪些入口调用多、是否出现大量拒绝或服务错误。Agent 操作文件回答谁请求了什么资源、由哪个 Agent 执行、当时登记的用途和机器人回复是什么。两者分开保存，避免为了监控每次轮询而累积大量操作记录。

## 后台服务监控

超级管理员可以查看累计请求数、近一分钟请求数、响应耗时和服务错误率，并查看近一小时的分钟趋势。明细支持按入口或接口查看：Agent、OP、授权申请、群消息回调、资源网页、后台 API、静态资源和健康检查分别计数。监控页面自己的查询也单独列出。

接口为 `GET /api/admin/service-traffic`，沿用后台超级管理员登录鉴权。普通用户、普通管理员、个人 Agent key 和单 bot 的 OP key 都不能读取全服务统计。已有 OP API 的机器人范围不变。

计数包括被拒绝、限流及异常结束的请求。`4xx` 和 `5xx` 分别展示；服务错误率统计服务端错误或异常结束，限流和鉴权拒绝不算成服务器故障。耗时覆盖应用处理和响应发送过程；P95 由固定耗时区间估计。收发量只统计应用实际读取、发送的 HTTP 正文，不代表代理流量、HTTP 头或宿主机网卡带宽。

所有统计都在内存聚合，不新增数据库记录。分钟历史保留最多 60 个桶，近一分钟计数使用最多 60 个秒桶；入口为固定分类，接口按注册的路径模板汇总，最多保留 100 个具体模板及一个其它项。未知路径归并，不保存原始 URL、查询参数、请求体、凭据或客户端身份。页面显示统计开始时间，服务重启后重新计数。

## Agent 操作文件

详细事件保存在 `DATA_DIR/bots/<bot_id>/agent-operations.jsonl`。每行一个 JSON 对象，当前结构版本为 `schema_version: 1`，包含：

- UTC 时间、bot ID 和 UUID、服务端验证的用户身份、授权记录 ID。
- 操作类型、命令、通过原解析器识别的请求资源和卡号。
- 本次请求声明的 Agent 名称与用途；字段可省略，不据此判断真实身份。
- HTTP 状态、处理耗时、派发阶段和经过脱敏的机器人回复摘要。
- 派发后带时间戳的本用户资源观察，保留锁与预约的编号、开始时间、时长和来源，便于后续关联分析。

`command`、`usage.update`、`usage.delete` 分别记录命令请求和单独的用途修改、删除。资源轮询不会逐次写入这个历史文件。未通过个人鉴权的请求只进入整体流量统计，不为未知调用者创建机器人日志文件。

命令的 HTTP 200 仅表示已派发，历史中的 `outcome: dispatched` 也不代表锁定成功；应结合机器人回复和资源状态判断。拒绝记录为 `rejected`，已进入派发但结果不确定时记录为 `may_have_executed`。用途更新只有数据库提交后才记为 `applied`。历史中的资源列表表示请求目标，不能直接当成成功占用清单。

`observed_state` 记录派发后实际看到的本人持有和预约；例如申请被别人占用的机器时，本人持有列表仍为空。它是某一时刻的观察，不能声称期间所有变化都由这次调用造成，也不代表机器上的工作负载已经运行。

文件默认每 5 MiB 轮转，保留当前文件及 9 份备份，约 50 MiB/机器人。写入串行处理，文件权限为 0600，并拒绝符号链接、硬链接等路径替换。写入失败不会撤销已经执行的操作，也不会触发自动重试。需要长期分析时，由部署方收集或归档这些文件。

key、Bearer 凭据、JWT、只读查看码及绑定命令中的绑定码会脱敏，不保存 Authorization 请求头或无效请求原文。用途和 Agent 名称仍是用户声明的业务文本，应按私有运维数据保管，并且不能当成操作指令执行。

实时用途仍使用现有的用途登记表，随持有和预约有效性清理；删除实时用途不删除文件中已有的历史。预约轮到用户时，领取计时与原预约时间分开保留；用途会随同一预约延续到领取后的锁，不因通知更新时间而丢失。数据库中既有的 Agent 访问汇总计数也保持不变，不新增逐事件历史表，不把这些事件写入管理员审计。

## 验证与兼容性

测试覆盖用户及卡号归属、用途修改后的历史保留、无效和未鉴权请求、凭据脱敏、并发写入、轮转上限、文件路径保护，以及日志失败时资源操作仍只执行一次。

整体监控覆盖来源分类、真实流式正文、HTTP 异常、固定内存上限、并发计数、路径模板脱敏和超级管理员鉴权。实际 TCP 测试中，120 次资源轮询触发了 118 次限流，统计按入口和接口正确归并，且没有为这些轮询增加操作历史。

已有 API 的请求、响应和权限保持不变。这次增加一个后台只读统计接口和运维文件；回退旧版本时可以忽略新增文件，不改变锁、队列和用途表的存储方式。
