# 资源续期与每人数量限制

锁定和预约是多人、多个 Agent 协作的依据。持有者延长时间会改变后续等待时间，同一个人反复申请也可能挤占资源。因此，这些规则应属于机器人本身，群消息和个人 Agent API 使用同一套校验。

## 兼容既有规则

原有版本只有 Agent API 的全局机器数保护，本次增加 bot 自身的续期和数量规则。已有 `RESOURCE_API_MAX_HELD_PER_IDENTITY` 默认 8，按同一机器人下用户已占用或预约的机器去重计数，按卡机器人同一机器的多张卡只算一台。这个保护继续在状态锁内执行，保留已发布 API 的原有语义；新增 bot 规则同时覆盖群消息。

## 禁止续期

机器人编辑页提供“禁止续期”开关，键名为 `FORBID_RELOCK`。适用于 NODE、DEVICE、QUEUE、QueueDevice；lock/slock 沿用原有语法，在修改状态前校验。

- 开启后，当前持有者不能通过重复 lock/slock 延长该资源；同一人的其他 Agent 也不能绕过。
- QUEUE、QueueDevice 中，当前持有者不能预约自己正在使用的资源。
- 已有预约的用户正常领取资源不属于续期。但开启时，领取时长不能超过自己的原预约时长；省略时长沿用预约时长。否则预约 1 小时、领取时改成 4 小时，仍会推迟后面的用户。
- 无人排队时也遵守开关，避免同一配置随队列变化而产生难以预期的行为。
- 释放后重新申请仍受原有队列顺序约束，不能绕过已有预约；没有其他等待者时允许重新申请。
- 不改变已有锁的到期时间，不自动释放，也不限制用户提前释放。

现有时长白名单只豁免最长租期，不自动豁免禁止续期和数量限制。已有抢占命令保持原权限边界，但不能被普通用户用来给自己的现有占用变相续期。

新建 QUEUE、QueueDevice 默认开启，新建 NODE、DEVICE 默认关闭。升级的已有机器人缺少该字段时保持原有允许续期的行为；只有管理员保存该配置后才改变规则，避免升级突然影响已有 Agent。

禁止续期能减少预计等待时间被延后的情况，但不承诺准确开工时间：管理员抢占、设备故障和用户未及时领取仍可能影响排队。

## 每人最多占用／预约资源数

编辑页提供数量项 `MAX_RESOURCES_PER_USER`，显示“不限”或正整数，默认不限（存储值 -1），不照搬参考项目固定的 16 台或 8 卡上界。

| 机器人类型 | 计数单位 |
|---|---|
| NODE、QUEUE | 每台机器算 1 个 |
| DEVICE、QueueDevice | 每张卡算 1 个，跨机器累计 |

合计当前用户已占用和有效预约的资源并去重。同一用户的所有 Agent、群消息与 API 共用额度；不同机器人分别计算。共享占用时，一张卡对该卡上的每个用户各算 1 个。已过期占用不应持续占用额度，过期判断沿用同一时刻的租约规则。

例如限额为 2：一个人已经持有卡 0，并预约卡 1，不能再申请卡 2；卡 1 从预约转为持有不增加计数。任务释放资源或取消预约后归还额度。

每次多目标申请先计算最终集合，在同一个状态锁内整体校验和修改；任一目标超限则整次拒绝，不部分成功。降低限额不会回收已有锁和预约；已有预约仍可正常领取，但超限用户不能继续新增资源。释放、取消预约和查询始终允许。

群消息中原本允许的 take 等取得资源操作也必须检查新增数量，不能通过更换命令绕过；OP 强制释放本身不取得资源，不受这个数量项限制。

现有 Agent API 的全局机器数保护保持不变。bot 数量限制与它分别校验：新限制按 bot 类型的资源单位计算，旧保护继续按机器计算，不能悄悄把已发布的“8 台机器”改成“8 张卡”。

## 页面、API 与 Skill

在机器人编辑页现有运行规则中用普通表单行展示开关和数量，点击保存后按既有配置更新流程生效，不增加立即生效接口或大块说明卡片。变更记录归入“修改 Bot 配置”的审计。

资源能力响应增量返回 `resource_policy`：`forbid_relock`、`max_resources_per_user`（-1 不限）、`resource_unit`（node/card）和个人接口中的 `claimed_resource_count`。只读网页返回前三项，不返回调用者计数。沿用现有鉴权、路径和命令响应约定，旧客户端可忽略新增字段。规则拒绝需要有清楚的中英文提示；HTTP 200 仍不等于成功获得资源。

Skill 要求 Agent 先读取当前规则：禁止续期时不能依赖自动续租，预约领取不能延长原预约时间；不允许释放后插队；多 Agent 需协调共享用户额度；失败后重新查询，不盲目重试。网页保持以资源和排队为主，只用简短文字标明当前规则。

## 实现验收

- 四种 bot 的新建、编辑、默认值、旧库升级及中英文页面。
- 禁止续期对群消息和 API 一致，支持多 Agent 共用用户身份。
- 续期、自己预约、队首领取、领取时长变长及释放重申请的边界。
- 跨机器、逐卡、共享占用、分次申请和并发申请的数量计数。
- 多目标拒绝无部分修改；调低限额不释放旧资源、不阻止旧预约领取。
- 已发布 API 机器数保护保持原语义，新增 bot 规则不会绕过它。
- Skill 和能力接口一致；原 lock 正则、状态存储和管理审计结构保持兼容。
