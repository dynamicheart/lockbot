# Agent API 群通知的延迟合并

## 问题与范围

同一机器人十秒内连续执行 `alias node-a`、`alias node-b`、`lock node-a,node-b 2h` 时，旧通知预算只让第一条发送，其余只计数而没有定时补发。操作本身与通知独立，不能把没有群通知理解为没有执行资源命令。

通知继续描述“Agent API 操作”，不把 HTTP 200 当成成功领取资源的证明。查询、帮助和轮询不产生群通知。公开信息只包含原通知允许的用户身份、操作命令和预设任务分类；Agent 名称及自由用途备注不进入队列。`alias` 通知只保留命令和资源目标，不公开其自由备注正文。私有操作历史保留原有权限与保留策略。

## 时序与边界

- 第一条通知保留同步行为；之后十秒窗口中的通知进入当前机器人的批次。窗口截止时间不随新操作延后，不需要第四个请求触发发送。
- 截止后，协调线程把该批次交给发送 worker。批次保留事件次序和用户/资源/命令，不把不同用户或 lock/unlock 转换压成一个匿名计数。
- 同一机器人同一时刻只发送一个批次。同步首条与后台批次共享最多两个发送名额；名额被占用时新请求只排队，不等待网络。首条兼容同步路径仍可能等待一次网络调用，并非所有通知都已异步化。
- 后台发送在资源状态锁和 API authority guard 外执行，持有当前代实例 lease 保护目标不被替换。每次平台调用只尝试一次；超时或异常为结果不确定，不自动重试。资源命令从不因通知失败被重放。
- 若后台发送在进入实例时遇到临时 admission 满额，尚未进行平台请求，可每秒重新尝试 admission，最长 120 秒。超过期限丢弃该批次并记录计数与警告；停止/退休或身份改变则直接取消。

## 容量与编码

队列是进程内、有限容量的通知设施，不是通用任务系统，不增加数据库表。最多保留 256 个机器人范围，每个范围最多 64 个待合并事件、64 KiB 待合并文本，外加至多一个已取出/延期批次。只淘汰没有待处理任务的范围。

正文按保守的应用预算拆分：最多 1800 个 Unicode 字符、4000 个 UTF-8 字节，包含事件间的空行和实际溢出说明。最终平台原生 JSON（包含 Unicode 转义与结构开销）另限 16 KiB；超限不发送并记录失败。这些是本应用的保守上限，不冒充平台最大允许值。正常三条短操作会合并成一条；较长批次按原顺序在后续窗口发送。

积压满时，新的资源变更优先替换尚未发送的 alias 通知；否则拒绝最新事件，不覆盖更早的资源变更。超长单事件也拒绝。所有丢弃均增加有界范围内的运行计数并记录不含任务正文的系统警告；可发送时追加公开的丢弃数量说明。全部机器人范围都繁忙时拒绝新范围并记录容量耗尽警告，不无限创建线程或排队。

## 目标复核与停用

待发批次携带机器人 UUID、identity revision、运行实例代号和目的地/凭据的摘要，不保留旧机器人对象或秘密明文。后台 flush 重新取得 live lease，读取最新数据库行，校验未删除、运行中、通知开关打开、身份版本与路由摘要相同。不能把旧群消息投向修改后的新群。

实例退休会清理对应旧代的待发通知；旧代的退休回调不能取消后来新代的任务。关闭通知会取消已有积压，再打开不会复活旧批次。发送前还检查批次的取消标记，避免排队等待 authority guard 时已被取消的批次因开关再次打开而复活。

平台 handoff 前的最后校验是停用边界。已经进入网络发送的通知无法由后续关停撤回；不能保证关闭开关后平台绝不再显示一条已在途的消息。

## 重启、退出与可观测性

待发内容仅在内存。正常退出、reset、停用或目标改变会清理待发项并记录取消数量；崩溃或进程被强杀时尚未发送的通知可能丢失，不能宣称持久交付或 exactly-once。重启不重放内存通知，更不会重放资源操作。已经平台接收不代表成员已读。

队列记录 queued、accepted、failed、unknown、deferred、cancelled、overflow/capacity drop 等运行计数，系统日志仅含 bot ID、数量、状态及固定原因，不含命令正文、用户任务、凭证或原始平台响应。这些计数随进程重启重置。没有使用新 OP 权限或把私有任务内容放进全局监控。

## 验收

确定性时钟覆盖 alias/alias/lock 三请求后的尾部发送、持续请求不延后截止时间、独立 bot/用户、顺序及消息拆分、中文和 native JSON 编码预算、溢出、发送不确定不重试、临时 admission、重置/退出、通知关闭再开启、删除/停止/身份和路由变更。适配器测试验证如流仅一次网络请求和平台接受结果解析。

上线前，在授权测试群使用虚构资源验证：连续两次 alias 再 lock，只出现首条即时通知和到期后的合并通知，合并消息保留锁操作和时长，且没有私密字段。另验证不同群路由与平台格式，随后才安排正式发布和部署。代码测试不等于真实群交付验收。
