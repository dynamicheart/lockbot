# 飞书接入收尾计划

这份清单记录本轮确认的范围和验收方式。完成一项就更新状态，不把讨论过的方案当作已实现。实现与如流并存，当前在本地测试；正式服务的发布和升级另行确认。

## 已定方案

- 企业应用在站点设置集中配置，一个应用通过明确的群路由服务多个独立资源机器人。
- 每个资源机器人创建时确定平台，编辑时不能换平台。
- 迁移采用“复制配置，跳转新建页面”。新旧机器人分别保存授权、锁和队列。
- 不做双平台共享资源池，不列为后续待办；不做一个资源机器人同时接如流、飞书。
- 不支持单聊。单聊事件直接忽略；不发送自动指引，不查询资源，不绑定授权，不执行命令。部署不要求单聊消息权限。
- 平台用户 ID 是鉴权依据，姓名只是展示，不能按同名用户跨平台合并。

## 逐项处理

| 问题 | 处理方式 | 当前状态与验收 |
| --- | --- | --- |
| 权限免审与审核分类 | 按应用身份逐项列出权限、用途、是否必需、控制台审核标记；区分权限免审、应用版本发布、成员范围审批 | 已核对本次使用的群 @、发送、群信息、用户基本信息、通讯录基本信息权限均标为免审；应用发布与成员范围仍按企业策略处理 |
| 姓名和 Open ID 交替出现 | 群消息与 Agent API 都在业务锁外预热当前用户姓名；查询失败保留最近已知姓名；冷缓存且权限不足才回退 ID | 修复中；需重启冷缓存后先调用 Agent API 验证 |
| 是否支持单聊 | 用户最终决定不开通；事件直接忽略，不发送指引，不要求单聊消息权限 | 已明确排除，保持当前群聊范围 |
| 飞书/如流编辑表单不一致 | 平台相关配置分区保持同样间距和帮助提示；飞书只选择中央应用与群，不重复输入 App Secret | 修复中；需逐个平台核对表单 |
| 飞书详情页混入如流凭证 | 隐藏如流回调、Webhook、Token、AES 字段；展示中央应用关联说明 | 修复中；不得隐藏通用 OP API 功能 |
| 群名无法识别 | 指定群查询、缓存、刷新；群名为主，Chat ID 次要展示并可复制 | 已实现，测试应用真实查名成功；未读取群历史或成员列表 |
| 群和资源如何关联 | 创建时由超级管理员选择应用和群；服务验证应用、租户、发送者及群路由；只有配置群的真实 @ 执行命令 | 基础隔离已实现并有回归；需补创建时的群可达性校验，明确机器人需在群内，不能仅凭 oc_ 字符串认为关联已验证 |
| 数据库和 key 如何兼容 | 如流原字段保留；飞书应用和群路由独立表；个人 key 保留平台范围；旧如流数据不自动转换 | 已实现基础结构；文档补充身份边界、备份恢复与回退限制 |
| 消息数据和渲染是否解耦 | 共用资源状态和命令执行；平台 Adapter 负责原生链接、提及和发送。业务层仍有格式化文本，不能宣称完全采用平台中立消息模型 | 基础 Adapter 已实现；本次记录真实边界，保持两平台格式测试，不重做通用聊天框架 |
| 内网飞书连接是否被监控 | 不代替企业给出合规结论，不绕过代理或 TLS 校验；说明目的域名、连接时长和流量可能被记录 | 说明已给出；需补到部署文档 |
| 指定飞书应用走代理 | 应用级配置，同时覆盖 API、SDK 握手和 WebSocket；凭证不回显，日志脱敏；不改变如流或全局代理 | 待实现；不能只设置 https_proxy 就宣称长连接已走代理，需实测 SDK 行为 |
| 复制机器人配置 | 只复制资源定义、规则、显示配置、Agent 开关；不复制群关联、应用凭证、个人授权、OP key、资源状态、队列、日志和用户例外名单 | 修复中；需检查跨平台新建及重复占用提醒 |
| 来源图标颜色 | 群消息蓝、Agent 紫、OP 橙；异常红；保留简洁布局和文字标签 | 已实现、本地已查看 |

## 顺序与交付

1. 完成姓名、详情页和复制配置，做针对性测试与本地界面验收。
2. 保持单聊不受支持，验证单聊不会执行命令或产生回复。
3. 实现应用级代理，分别验证 HTTP API 和 WebSocket，不仅看“进程已启动”。
4. 补齐权限表、数据库/渲染边界、复制迁移和网络部署说明。
5. 复核如流回归、飞书真实群及单聊、备份恢复；更新原 PR，等待当前提交 CI 通过。未经另行安排不升级正式服务。
