# 飞书接入：当前整合与上线门槛

PR #25 与如流并存，保持草稿。当前源码已整合 `release/2.x` 的严格任务隐私、历史/OP 公开历史、通知尾部队列和旧日志 scope 修复；正式服务仍为 v2.15.2，不包含飞书。本轮只运行隔离本地测试，没有重启接收端或发送真实群消息。

## 已定边界

- 一个企业应用可关联多个独立资源群，每群对应一个资源 bot。平台创建时固定；迁移仅复制安全配置到新建页面。
- 不做双平台共享资源池，也不让一个资源 bot 同时接如流和飞书。管理同一批真实资源时，先停旧入口，避免两套独立锁并存。
- 不支持单聊，直接忽略、不自动发帮助、不绑定、不执行资源命令，不申请单聊权限。
- 用户身份使用平台和稳定 ID；姓名只是展示。相同姓名不合并平台身份，OP key 不继承创建者的私密任务权限。
- 代理由超级管理员站点设置统一选择继承 `LOCKBOT_FEISHU_PROXY_URL`、直连或指定代理，覆盖 API/SDK 握手/WebSocket；不修改全局或如流代理。逐应用独立代理 UI 未实现，不列作本轮必需接口。

## PR #23 的关系

PR #23 是独立的开发消息 gallery，默认 dry-run，显式发送才访问目标群；它不是生产接收器或 PR #25 的运行依赖。旧的授权群平台接收记录只证明那些样例当时被接受，不能证明当前 Adapter、通知或隐私整合已经实测。PR #25 的 Adapter/ingress 测试是本轮主验证；整合后可将 gallery 用作双方共享的手工视觉清单。未合入 #23 前不要把它的脚本写成已发布工具，也不要为 gallery 再开一个应用接收器。

## 权限与如流差异

[部署文档](../usage/feishu.md) 记录最小群 @ /发送权限、可选姓名/群信息权限，以及本次测试企业控制台的免审标记。免审不是免应用发布、免成员/通讯录范围审批或免企业网络管理。首次接入仍要分别确认应用身份、成员可用范围、发布状态、机器人在资源群内和显式群路由。如流的独立机器人 Webhook/Token/AES 不等于飞书企业应用共享凭证；不可搬用两套 key 或按同名用户迁移身份。

- [ ] 明确唯一测试接收端，保留已有凭证和如流配置后，再安排冷启动/断线重连及无重复接收端检查。
- [ ] 使用当前候选版本，在授权群重验查询、短锁/排队/提醒、Agent 绑定、原生链接/@与公开通知分类；不发送私密备注或新建未经授权的真实资源任务。
- [ ] 当前候选版本真实验证普通 owner/OP 与 super-admin 权限差异，分别检查个人 API、共享网页、历史/下载；旧测试候选未包含严格隐私时的结果不能替代。
- [ ] 核对群内机器人、成员可用范围及群名/姓名权限失败退化；验证至少两个群/资源 bot 不串身份或状态。
- [ ] 在实际客户端复核 emoji、链接、@用户/@全体、长回复与窄屏；平台接受并不代表用户已读或最终渲染正确。
- [ ] 完成发布/升级/回退计划和备份恢复演练；当前本地整合或测试环境运行不等于正式飞书上线。保持 PR 草稿直到必需门槛确认。

真实验收执行顺序与最小证据见 [候选验收执行单](../development/feishu-live-acceptance.md)。

站点代理已增加超级管理员专属持久三模式（部署继承/直连/指定无凭据代理），HTTP 和 SDK 子进程共用有效策略，传输变化后先停止旧接收端再连接。尚不提供每应用独立代理；需补当前候选保存/重启/真实握手验收。固定官方 HTTP 测试不代表 WebSocket 或群消息成功。

已对测试候选的群名普通读取与显式刷新接口实际确认 HTTP 200 且有名称；这不证明此前临时失败不存在，也不据此推断应用缺权限。界面保留旧名称时明确标注缓存，并区分读取权限不足与暂时刷新失败，提供重试。站点飞书代理仍需新候选真实保存/重启验收；审计 action 的中文显示由独立 PR #50 跟踪，不改变权限或原始 action 标识。


### 最小联系人与单聊边界

核心群接入使用群内真实 @ 的接收与机器人发送权限。联系人姓名解析不是资源命令/鉴权/Agent绑定前提，但完整姓名化后台需要组合保留两个不同层面的权限：[官方获取用户信息接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/contact-v3/user/get)列出 `contact:contact.base:readonly` 为API调用权限，`contact:user.base:readonly` 为 name 等字段权限。它们互补，不是“宽权限和窄权限可以互换”的关系；不将前者判为冗余，也不计划撤销这两项。查询仍限制在应用允许的可用/数据范围，不读取手机号、邮箱，不新增群成员遍历范围。

单聊继续忽略，不补开单聊权限或新增帮助回复。测试应用的 `im:message.p2p_msg:readonly` 已由控制台独立关闭，控制台确认立即生效且当前修改均已发布。两项联系人权限保持原样。缺少姓名查询或无可用缓存时，文本/网页/API安全回退稳定Open ID；原生 @ 由飞书客户端解析平台名，姓名查询成功也不改变鉴权身份或保证所有用户均可查名。

控制台“免审”描述审批类型，“是否核心命令/姓名化后台所需”描述不同产品能力的依赖，不能互推。权限已开通、应用已发布、用户在应用可用范围和机器人已进资源群仍需分别确认。
